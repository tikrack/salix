salix

A small, complete ORM for the Salam language. Define a model, and salix renders the SQL — on SQLite, MySQL/MariaDB and PostgreSQL, from one config file.

One model, three engines.

Change the engine by editing salix.ini — no code changes. Identifiers are quoted for the active engine, and literals go through the driver's Quote, which handles escaping.

An auto key becomes INTEGER PRIMARY KEY AUTOINCREMENT on SQLite, BIGINT AUTO_INCREMENT PRIMARY KEY on MySQL, and BIGSERIAL PRIMARY KEY on PostgreSQL. Column helpers: NewColumn, AutoKeyCol, PrimaryKeyCol, NotNull, Unique, WithDefault.

Describe the table in the model.

A model is a struct that implements five methods. That is the whole contract — salix derives names, types, the primary key and auto-increment behaviour from the columns you declare.

  • Table()the table name
  • ColumnCount()how many columns
  • Column(i)column i: name, type, constraints
  • Get(col)value out, as a salix.Value
  • Set(col, v)store one salix.Value into a column

Open a session, get a typed repo.

OpenFile(path) is a shortcut for a SQLite file, and Wrap(conn, engine, debug) adopts an existing db.Connection.

Querying without string-building

Conditions are built with the session, so identifiers and literals are quoted for the active engine: Eq Ne Lt Le Gt Ge Like InList Between IsNull IsNotNull, combined with And, Or, Not and Raw. Order with Asc and Desc.

For ad-hoc SQL use s.Query(sql), which returns a Vector of Row, or s.One(sql). Row exposes Int, Float, Bool, Text, IsNull, At, NameAt and Free; free the vector with rows.free().

Migrations and transactions.

Save returns the new row id: the native last-insert id on SQLite and MySQL, and RETURNING on PostgreSQL. SaveMany(items) inserts a batch inside one transaction.

Notes and limits

  1. Identifiers are quoted with double quotes on SQLite and PostgreSQL and backticks on MySQL; literals go through the driver's Quote.
  2. int is 32-bit. Model integer columns are declared i64 so SQL BIGINT and Salam i64 line up for ids, counts and timestamps.
  3. PostgreSQL results are materialised, so page large tables with List(..., limit) or Page(...) rather than scanning everything at once.
  4. MySQL connections are not thread-safe: give each thread its own connection and call LibraryInit and ThreadInit as described in the Salam database guide.
  5. The ORM renders SQL directly from the model's values. Values are quoted by the driver, so they are safe; never splice untrusted text into a where string by hand — build it with the condition helpers.
